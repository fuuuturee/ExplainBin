# Architecture

## Goals

ExplainBin is built around four constraints:

1. **Never execute or load the analyzed file.** The sample is handled as bytes, never as an image.
2. **Survive malformed input.** Every offset and size is validated before use; limits cap counts and recursion.
3. **Explain, do not score.** Findings carry evidence, impact, benign alternatives and next steps. No malware percentage is computed.
4. **Stay local.** No uploads, no sample traffic, no online revocation lookups. Reports are written only where the user chooses.

## Layers

```
┌──────────────────────────────────────────────────────────────┐
│ Qt 6 UI (src/ui, include/explainbin/ui)                      │
│ Dashboard · Analysis · PE · Imports · Signature · Findings    │
└──────────────────────────────┬───────────────────────────────┘
                               │ AnalysisResult (value type)
┌──────────────────────────────▼───────────────────────────────┐

└──────────────────────────────┬───────────────────────────────┘
                               │
┌──────────────────────────────▼───────────────────────────────┐
│ Core (src/core)                                              │
│ Analyzer orchestrates:                                       │
│ FileReader → HashCalculator                                  │
│            → PEParser → EntropyAnalyzer → ImportAnalyzer     │
│            → SignatureVerifier → FindingsEngine              │
└──────────────────────────────┬───────────────────────────────┘
                               │ Windows APIs
                    bcrypt · crypt32 · wintrust
```

The core and reports libraries do not depend on Qt. The CLI links the same code as the GUI.

## Data flow

1. `Analyzer::analyze` records file identity from the path (name, extension) and starts a timer.
2. `FileReader::read` opens a read-only handle with `FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`, checks the configured size limit, reads metadata and copies the file into a single `std::vector<std::uint8_t>`.
3. `HashCalculator` hashes that exact buffer with CNG (SHA-256, SHA-1, optional MD5).
4. `PEParser` parses the buffer with a bounds-checked `Reader`. It validates the DOS header, `e_lfanew`, NT signature, COFF header, optional header magic/size, section table and each data directory. Directories are mapped through sections (or headers) before use.
5. `EntropyAnalyzer` computes whole-file and per-section Shannon entropy for ranges that are fully backed by the file.
6. `ImportAnalyzer` annotates imported functions with categories/insights and evaluates capability combinations.
7. `SignatureVerifier` verifies an embedded Authenticode signature with WinVerifyTrust (`WTD_CACHE_ONLY_URL_RETRIEVAL`, `WTD_REVOKE_NONE`) and extracts signer details with CryptQueryObject. When no embedded signature exists, it looks for the file hash in locally installed Windows catalogs (`CryptCATAdmin*`) and verifies the matching catalog. Revocation is explicitly marked as not checked online.
8. `FindingsEngine` evaluates structural and signature rules. Import rules are merged and findings are deduplicated by ID and sorted by severity.
9. Exporters render the `AnalysisResult` as JSON, HTML or text.

## Safety model

### Input handling

- The file is never mapped as an image, executed, loaded with `LoadLibrary`, or passed to a debugger.
- The read is capped at `AnalysisOptions::maxFileSizeBytes` (default 256 MiB).
- All parsing reads go through `Reader`, which checks `offset <= size && length <= size - offset` before every access. This avoids overflow and out-of-range reads.
- Multi-byte reads are assembled byte-by-byte to avoid alignment and endianness assumptions.
- `mapRva` requires the entire requested range to be backed by a section's raw data, and rejects unmapped or virtual-only ranges.
- Counts are capped: 96 sections, 1024 import descriptors, 8192 thunks per library, 16384 exports, 4096 resources, 64 debug entries, 128 TLS callbacks.
- The resource tree tracks visited directories to stop cycles and limits depth.
- Any inconsistency becomes a `Diagnostic`; parsing continues where safe and `PeInfo::partial` is set.
- Untrusted strings are sanitized (printable ASCII, bounded length) before they reach the UI or reports.

### Report output

- JSON is generated with nlohmann/json, so escaping is handled by the library.
- HTML is generated by hand but every interpolated value passes through `escape()`, which escapes `& < > " '` and converts newlines.
- Report writing uses a binary truncating stream and reports failures to the caller.
- The CLI writes only to explicit `--json`, `--html` and `--text` paths.

### Signature verification

- WinVerifyTrust runs with no UI and a file-based subject.
- Revocation checks are intentionally disabled (`WTD_REVOKE_NONE`) and URL retrieval is cache-only, so analysis never contacts the network.
- If no embedded signature exists, `SignatureInfo::catalogSigned` reports whether a locally installed Windows catalog contained the file hash and verified successfully. Catalog lookup uses local catalogs only.
- `SignatureInfo::revocationChecked` is `false` and reports state this explicitly.
- A valid signature is reported as provenance/integrity evidence, never as proof of safety.
- If verification is disabled, the status is `NotChecked` and no unsigned finding is emitted.

## Threading

The GUI runs `Analyzer::analyze` through `QtConcurrent::run` and observes it with `QFutureWatcher<AnalysisResult>`. The core is stateless per call and contains no global mutable state; separate `Analyzer` instances can run concurrently. Hash algorithms are created per invocation.

## Extensibility

- **New finding rules:** implement in `FindingsEngine`/`ImportAnalyzer`, add tests and document the rule.
- **New reports:** implement `IReportExporter` and register the format in the CLI/UI.
- **New parser data:** extend `PeInfo`, parse it behind bounds checks, expose it in JSON and the relevant UI view.
- **Other front ends:** link `explainbin_reports` (or just `explainbin_core`) and consume `AnalysisResult`.

## Known limitations

- PE only; no ELF, Mach-O or .NET metadata deep analysis.
- No disassembly, control-flow analysis, emulation or unpacking.
- Imports can be resolved dynamically and are not visible statically.
- Certificate revocation is not checked online.
- Catalog-signed files may appear unsigned when no embedded signature exists.
- Heuristics are intentionally conservative and context-dependent.
